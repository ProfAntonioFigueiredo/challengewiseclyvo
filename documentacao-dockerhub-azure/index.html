Java Spring Boot em containers: MySQL para aula e Oracle para o Challenge

Material academico, navegavel e passo a passo para conduzir a aula com a aplicacao modelo Java + MySQL e reproduzir a entrega oficial com Java + Oracle usando Docker, Docker Hub, Azure VM e a imagem gvenzl/oracle-xe:21-slim.

Visao Geral Arquitetura PPTs Aula - 8 Passos Challenge - 8 Passos Criterios Evidencias Troubleshooting

1. Visao geral do material

Este HTML foi estruturado como um roteiro de aula e como um roteiro de entrega. A primeira parte demonstra o ciclo DevOps com a aplicacao de referencia, usando Java/Spring Boot e MySQL. A segunda parte repete os mesmos 8 passos com o padrao exigido para o Challenge: aplicacao Java/Spring Boot dos alunos e banco Oracle em container Docker.

Dois cenarios no mesmo material
Cenario A - Aula guiada

Professor conduz os alunos usando o projeto de referencia portalweb, Java/Spring Boot, MySQL, Docker Compose e deploy em VM Azure.

Cenario B - Challenge

Alunos reproduzem os mesmos passos com a propria aplicacao, usando Java/Spring Boot ou .NET, banco Oracle conteinerizado e CRUD funcional.

Resultado esperado

Aplicacao em nuvem, containers em background, imagem no Docker Hub, volume persistente, evidencias tecnicas e acesso externo para avaliacao.

Mensagem para os alunos: a entrega precisa funcionar em nuvem. Se a aplicacao ficar apenas em localhost, a banca nao conseguira validar a execucao pratica completa.

A arquitetura abaixo representa o fluxo que deve ser seguido nos dois cenarios. No cenario de aula, o banco e MySQL. Criar Dockerfile com possibilidades principais e Docker Compose

O Dockerfile e a receita da imagem. O Docker Compose coordena a aplicacao com dois containers. Nesta etapa, o professor deve explicar as instrucoes principais do Dockerfile e as secoes essenciais do Compose.

InstrucaoSignificado no Dockerfile
FROMInicializa o build de uma imagem a partir de uma imagem base.
RUNExecuta um comando durante o processo de construcao.
WORKDIRDefine o diretorio corrente.
COPYCopia arquivos ou diretorios para o sistema de arquivos da imagem.
ADDCopia arquivos, diretorios ou arquivos remotos para a imagem.
LABELAdiciona metadados a imagem.
ENVDefine variaveis de ambiente.
VOLUMEDefine volumes que devem ser usados pelo container.
ARGDefine argumento usado no processo de build.
EXPOSEDocumenta a porta que o container utiliza.
USERDefine o usuario que executara o processo no container.
CMDDefine comando ou parametros padrao.
ENTRYPOINTConfigura o container para ser executado como um executavel.
 
FROM maven:3.9.9-eclipse-temurin-17 AS build
WORKDIR /build
COPY pom.xml pom.xml
COPY src src
RUN mvn clean package -DskipTests

FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=build /build/target/portalweb-1.0-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
docker compose config

Compose: explicar services, image, build, ports, depends_on, environment, networks e volumes.

Criar e executar o container Docker localmente

Nesta etapa, a imagem vira container. O comando abaixo cria o container WISE-CLYVO, publica a porta da aplicacao e executa em background.

Clone, adequar e compilar a aplicacao do grupo

O grupo deve clonar o proprio repositorio, adequar a aplicacao ao problema escolhido no Challenge e compilar localmente antes de criar imagens Docker. A aplicacao nao deve ser apenas uma copia do CRUD de aula: ela precisa resolver um problema dentro da jornada CLYVO VET.

  • Escolher uma dor real da jornada: preventivo, continuidade clinica, emergencia, relacionamento ou inteligencia de dados.
  • Definir entidades e relacionamentos coerentes com o DER.
  • Implementar CRUD completo com GET, POST, PUT e DELETE.
  • Inserir pelo menos dois registros significativos para demonstracao.

Criar Dockerfile, Docker Compose e configurar Oracle

O banco de avaliacao sera Oracle em container. A aplicacao precisa usar driver JDBC Oracle, URL apontando para o nome do servico Docker oracle-db, Dockerfile da aplicacao e Compose com App + Banco.

<dependency>
  <groupId>com.oracle.database.jdbc</groupId>
  <artifactId>ojdbc11</artifactId>
  <scope>runtime</scope>
</dependency>
spring.datasource.url=${SPRING_DATASOURCE_URL:jdbc:oracle:thin:@localhost:1521/XEPDB1}
spring.datasource.username=${SPRING_DATASOURCE_USERNAME:APP_USER}
spring.datasource.password=${SPRING_DATASOURCE_PASSWORD:AppPassword123}
spring.datasource.driver-class-name=oracle.jdbc.OracleDriver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.OracleDialect
server.port=8080

Atencao: tabelas, constraints e scripts SQL devem estar coerentes com o projeto de Java ou .NET entregue pelo grupo.

Criar imagem Docker pelo processo de build e versionar TAGs

O Challenge penaliza aplicacao rodando como root. Por isso, o Dockerfile da entrega deve criar usuario dedicado. Em seguida, o grupo deve gerar imagens versionadas, por exemplo challenge-clyvo:v1, v2, v5 e v8.

FROM maven:3.9.9-eclipse-temurin-17 AS build
WORKDIR /build
COPY pom.xml pom.xml
COPY src src
RUN mvn clean package -DskipTests

FROM eclipse-temurin:17-jre
RUN groupadd --system appgroup && useradd --system --gid appgroup appuser
WORKDIR /app
COPY --from=build /build/target/*.jar app.jar
RUN chown -R appuser:appgroup /app
USER appuser
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
docker build -t challenge-clyvo:v1 .
docker build -t challenge-clyvo:v2 .
docker build -t challenge-clyvo:v5 .
docker image ls challenge-clyvo
docker run --rm --entrypoint whoami challenge-clyvo:v1

Criar e executar o container local com Docker run e Compose

O docker run demonstra a execucao da imagem como container. Para a solucao completa, o Compose sobe aplicacao e Oracle na mesma rede. O banco precisa usar volume nomeado para persistencia.

services:
  oracle-db:
    image: gvenzl/oracle-xe:21-slim
    container_name: oracle-db
    environment:
      ORACLE_PASSWORD: "OracleRoot123"
      APP_USER: "APP_USER"
      APP_USER_PASSWORD: "AppPassword123"
    volumes:
      - oracle_data:/opt/oracle/oradata
      - ./sql:/container-entrypoint-initdb.d
    healthcheck:
      test: ["CMD-SHELL", "healthcheck.sh"]
      interval: 10s
      timeout: 5s
      retries: 15
      start_period: 40s
    networks:
      - challenge_net
    restart: unless-stopped

  portalweb:
    build: .
    image: portalweb-oracle:local
    container_name: portalweb
    depends_on:
      oracle-db:
        condition: service_healthy
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: "jdbc:oracle:thin:@oracle-db:1521/XEPDB1"
      SPRING_DATASOURCE_USERNAME: "APP_USER"
      SPRING_DATASOURCE_PASSWORD: "AppPassword123"
    networks:
      - challenge_net
    restart: on-failure

networks:
  challenge_net:
    driver: bridge

volumes:
  oracle_data:

Criar a infraestrutura de producao utilizando Azure CLI

O script deve criar Resource Group, VNet, Subnet, NSG, VM Standard_B4ls_v2 com 8GB de memoria, discos e regras de inbound/outbound. Ele e um dos entregaveis avaliados.

#!/usr/bin/env bash
set -e

RG="rg-challenge-clyvo-vet"
LOCATION="brazilsouth"
VNET="vnet_wise_dev"
SUBNET="sub_net_dev"
NSG="nsg_portalweb_dev"
VM="vm-wise-clyvo-dev-01"
ADMIN="azureuser"

az group create --name "$RG" --location "$LOCATION"

az network vnet create \
  --resource-group "$RG" \
  --location "$LOCATION" \
  --name "$VNET" \
  --address-prefixes 10.10.0.0/16 \
  --subnet-name "$SUBNET" \
  --subnet-prefixes 10.10.1.0/24

az network nsg create \
  --resource-group "$RG" \
  --location "$LOCATION" \
  --name "$NSG"

az vm create \
  --resource-group "$RG" \
  --name "$VM" \
  --image Ubuntu2204 \
  --size Standard_B4ls_v2 \
  --admin-username "$ADMIN" \
  --generate-ssh-keys \
  --vnet-name "$VNET" \
  --subnet "$SUBNET" \
  --nsg "$NSG"

az vm open-port --resource-group "$RG" --name "$VM" --port 22
az vm open-port --resource-group "$RG" --name "$VM" --port 8080
az vm open-port --resource-group "$RG" --name "$VM" --port 1521

az vm run-command invoke \
  --resource-group "$RG" \
  --name "$VM" \
  --command-id RunShellScript \
  --scripts "sudo apt-get update && sudo apt-get install -y git nano curl ca-certificates && curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $ADMIN"

az vm show \
  --resource-group "$RG" \
  --name "$VM" \
  --show-details \
  --query publicIps \
  --output tsv

Para nota maxima: documentar Resource Group, VM, portas liberadas, Docker instalado e ferramentas instaladas.

6. Criterios de avaliacao e penalidades

DevOps Tools & Cloud Computing

Item O que deve ser demonstrado Pontuacao
Script Azure CLI Provisionar VM Linux, abrir portas, instalar Docker e ferramentas necessarias. ate 20 pontos
Execucao em nuvem App e Banco em Docker, execucao em background, usuario sem privilegio administrativo e volume nomeado. ate 60 pontos
Arquitetura macro Desenho com usuario, API, banco, VM, containers, rede, portas, volumes, Docker Hub e fluxo de acesso. ate 20 pontos

Requisitos tecnicos de desenvolvimento

  • CRUD completo com GET, POST, PUT e DELETE.
  • Persistencia em banco Oracle conteinerizado neste roteiro. Para a demonstracao do professor e correcao desta arquitetura, nao usar mock nem H2 em memoria.
  • Entidades relacionadas e mapeadas com JPA.
  • DTOs, Bean Validation, paginacao, ordenacao, busca por parametros, cache, tratamento de erros e Swagger.
  • Collection Postman ou Insomnia exportada para o professor validar.
  • DER e modelo fisico coerentes com a aplicacao.

Penalidades criticas

  • Entrega apenas em localhost: correcao pratica inviabilizada.
  • Projeto nao executando em background: perda de pontuacao.
  • Aplicacao rodando como root: perda de pontuacao.
  • Banco sem volume nomeado: perda relevante de pontuacao.
  • Nao mostrar cada operacao no banco: perda relevante de pontuacao.
  • GitHub sem How To, descricao, beneficios, Dockerfile/Compose ou script Azure CLI: perda de pontuacao.
  • Professor sem acesso ao GitHub ou ao video: correcao pode ser inviabilizada.

8. Troubleshooting orientado

Problema Verificacao Acao recomendada
Aplicacao nao abre pelo IP publico docker compose ps, NSG, porta 8080 Confirmar se a porta esta aberta na Azure e se o Compose mapeia 8080:8080.
Banco Oracle demora para iniciar docker logs oracle-db -f Aguardar a primeira inicializacao e manter healthcheck com tempo suficiente.
App inicia antes do banco Logs da aplicacao e healthcheck Usar depends_on com condition: service_healthy.
Dados desaparecem docker volume ls Usar volume nomeado e nao executar docker compose down -v antes da avaliacao.
Imagem nao encontrada na VM docker pull usuario/imagem:tag Verificar usuario Docker Hub, nome do repositorio, tag e visibilidade da imagem.
Perda por usuario root docker exec portalweb whoami Criar usuario no Dockerfile e usar USER appuser.
